# 모의고사 점수 입력·조회 기능 설계

작성일: 2026-09-03

## 1. 배경과 목표

학생이 전국 모의고사(학력평가/모의평가) 영어 점수를 직접 입력하면,

- **학생**은 성적표에서 자기 점수·등급·학년 등수와 회차별 추이 그래프를 본다.
- **선생님**은 반 단위 관리 화면에서 우리 반 제출 현황·점수·학년 등수를 보고, 우리 반 평균과 학년 평균을 비교한다.

등수는 **학원 전체의 같은 학년 학생을 통합**해서 낸다. 모의고사는 전국 동일 시험이므로 반 안에서만 등수를 내는 것은 의미가 약하다.

이력은 학년이 올라가도 이어진다. 이 학원은 **반이 통째로 진급**하므로(반의 학년만 바꾼다) 학생 ID가 바뀌지 않는다 — 7장 참고.

### 확정된 정책 결정

| 항목 | 결정 |
|---|---|
| 등수 범위 | 학원 전체 동일 학년 통합 |
| 입력 항목 | 영어 원점수(숫자) + 등급(1~9 드롭다운, 선택) |
| 회차 개설 | 관리자(마스터)가 학년별로 개설 |
| 반영 시점 | 제출 즉시 반영, 선생님이 수정·제외 가능 |
| 학생 노출 | 내 점수·등급·등수 + 익명 분포. 다른 학생 이름·점수는 노출하지 않음 |
| 학년 입력 | 회차 개설과 학교 설정 모두 드롭다운 선택 (자유 입력 금지) |
| 등급 입력 | 학생이 1~9 드롭다운으로 선택. 원점수→등급 자동 환산 없음 |
| 등수 공개 | 입력 마감 후에만 학생에게 공개 |
| 소수 보호 | 응시자 5명 미만이면 학생에게 등수·평균 비공개 |

## 2. 데이터 모델

기존 `school` blob(수백 KB~1MB)에 넣지 않고 **별도 Redis 키 공간**을 쓴다. 학년 등수를 내려면 그 학년 전원을 한 번에 읽어야 하는데, blob 방식은 반 개수만큼 큰 blob을 읽어야 하고 학생 제출이 성적 일괄저장과 쓰기 충돌을 일으킨다. 이미 `school:summary` 해시에서 검증된 패턴을 그대로 따른다.

```
mock:rounds            (Hash)  roundId   -> 회차 정의 JSON
mock:sub:<roundId>     (Hash)  studentId -> 제출 1건 JSON
mock:agg:<roundId>     (Key)   집계 캐시 JSON
```

### 2.1 회차 (`mock:rounds` 필드값)

```js
{
  id: 'mr1774...',            // 'mr' + Date.now()
  grade: '1학년',              // normalizeGrade() 통과값. school.grade와 매칭하는 키
  title: '2026년 3월 학력평가',
  examDate: '2026.03.26',     // 응시일. 정렬·표시 기준
  openAt: 1774000000000,      // 입력 시작 (ms)
  closeAt: 1774600000000,     // 입력 마감 (ms). 이후 학생 입력/수정 잠김
  maxScore: 100,
  createdBy: 'admin-actor-id',
  createdAt: 1773900000000,
  archived: false
}
```

### 2.2 제출 (`mock:sub:<roundId>` 필드값)

**필드 키는 `studentId` 하나**다. 학생 ID는 전역 유니크하다 (`api/admin/[action].js`의 `next-student-id`가 전역 카운터로 채번하고, `findStudentByCredentials`의 로그인도 이미 이 가정 위에 서 있다). `schoolId`를 키에 넣지 않으므로 반이 학년을 올리거나 이름이 바뀌어도 `HGET` 한 번으로 본인 기록을 찾는다.

```js
{
  sid: 's412',
  schoolId: 'sch1',             // 제출 당시 반 (스냅샷)
  schoolName: '고양국제고 1-A',  // 제출 당시 반 이름 (스냅샷)
  name: '홍길동',                // 제출 당시 이름 (스냅샷)
  score: 88,                    // 0 ~ maxScore 정수
  grade: 2,                     // 1~9 또는 null
  submittedAt: 1774100000000,
  updatedAt: 1774100000000,
  editedBy: null,               // 선생님이 고쳤으면 관리자 actorId
  excluded: false,              // true면 등수·평균·분포에서 완전 제외
  memo: ''                      // 선생님 메모 (제외 사유 등)
}
```

**반 이름·학생 이름을 스냅샷으로 박는 이유**: 회차를 열 때마다 학교 blob 수십 개를 읽지 않아도 되고, 반 이름이 `1학년 A반`에서 `2학년 A반`으로 바뀌어도 그 회차 당시 소속이 보존된다. 개인 이력은 `sid`로 묶이므로 학년이 올라가도 끊기지 않는다 — 표시상의 소속만 그때 것으로 남는다.

### 2.3 집계 캐시 (`mock:agg:<roundId>`)

```js
{
  count: 84,                    // 유효 응시자 수 (excluded 제외)
  avg: 71.4, max: 98, min: 32,
  rankOf: { 's412': 12 },       // studentId -> 학년 등수
  rankCounts: { 1: 1, 12: 3 },  // 등수별 인원 (동점자 수 표시용)
  gradeDist: { 1: 4, 2: 9 },    // 등급 분포 (학생 익명 그래프)
  bySchool: {                   // 반별 요약 (선생님 비교 그래프)
    sch1: { count: 14, avg: 76.2, max: 98 }
  },
  computedAt: 1774100000000
}
```

제출·수정·제외가 일어날 때마다 재계산한다. 회차당 응시자는 수십~수백 명이라 `HGETALL` + 정렬이 밀리초 단위다. 캐시가 없거나 읽기에 실패하면 그 자리에서 다시 계산해 저장한다(`school:summary`의 self-healing과 같은 방식).

### 2.4 학년 정규화

`school.grade`는 자유 텍스트라 `1학년`, `고1`, ` 2학년 `이 섞일 수 있다. 섞이면 등수가 두 덩어리로 쪼개져 "1등"이 두 명 나오는데, 화면상 알아채기 어렵다.

- `normalizeGrade(s)`: 공백 제거 + 별칭 매핑(`고1`→`1학년` 등)
- **회차 개설 화면과 학교 설정 화면 모두 학년은 드롭다운**이다. `getSchoolSummaries()`(이미 `grade` 필드를 갖고 있다)에서 현존 학년을 뽑아 정규화·중복제거해서 목록으로 만든다. 학교 설정 쪽은 `+ 새 학년 입력`도 허용한다(7.1).

## 3. API

Vercel Hobby 함수 12개 한도에 **이미 도달**했으므로(`api/` 아래 함수 파일이 정확히 12개) 새 serverless 함수 파일을 만들지 않는다. 기존 동적 라우트에 action만 추가한다. 로직은 `api/_lib/mock.js`에 모은다(`_lib`은 번들되므로 함수 수에 잡히지 않는다).

### 3.1 학생 — `api/student/[action].js`

**`GET /api/student/mock`**

`mock:rounds`를 통째로 읽은 뒤 두 가지를 서로 **다른 기준으로** 뽑는다.

- `openRound` (입력칸을 띄울 회차): **지금 내 학년**이 회차의 `grade`와 같고, `openAt <= now < closeAt`인 것
- `history` (지난 기록): **내가 실제로 제출한 모든 회차.** 학년으로 거르지 않는다

`history`를 학년으로 거르면 안 된다. 진급은 반의 `school.grade`만 바꾸는 방식이므로(7장), 2학년이 되는 순간 1학년 회차가 목록에서 빠져 **이력이 화면에서 사라진다** — 데이터는 남아 있는데 안 보이는, 알아채기 어려운 형태의 손실이다.

회차별 제출·집계는 **파이프라인 한 번**으로 읽는다(회차 N개면 `HGET`/`GET` 2N개 명령, 왕복 1회).

```js
{
  openRound: {                  // 지금 입력 가능한 회차 (없으면 null)
    id, title, examDate, closeAt, maxScore,
    mySubmission: { score, grade, updatedAt } | null,
    submittedCount: 62, totalCount: 84   // "84명 중 62명 입력"
  },
  // totalCount = 그 학년 반들의 studentCount 합. school:summary 해시(HGETALL 1회)에서
  // grade가 일치하는 항목만 더한다 — 학교 blob을 읽지 않는다.
  // submittedCount = HLEN mock:sub:<roundId>

  history: [                    // 내가 제출한 마감된 회차 전부, 응시일 오름차순 (학년 무관)
    {
      roundId, title, examDate, grade: '1학년', maxScore,
      score: 88, myGrade: 2,
      rank: 12, tieCount: 3, count: 84,   // count<5면 rank/tieCount/avg/max는 null
      avg: 71.4, max: 98,
      gradeDist: { 1: 4, 2: 9 }
    }
  ]
}
```

**다른 학생의 이름·점수는 어떤 경우에도 응답에 포함하지 않는다.** 기존 성적표 API가 `_aggregates`만 내려보내는 정책과 동일하다.

**`POST /api/student/mock-submit`** — body `{ roundId, score, grade }`

- `isSameOrigin` 확인
- 회차 존재 확인, `openAt <= now < closeAt` 아니면 403 (`입력이 마감되었습니다`)
- 회차의 `grade`가 내 학교 학년과 일치하는지 확인 (불일치 403)
- `score`: 정수, `0 <= score <= maxScore` 아니면 400
- `grade`: 1~9 정수 또는 null 아니면 400
- `HSET mock:sub:<roundId> <sid> <json>` — **필드 1개 쓰기**라 학생끼리도, 선생님 일괄저장과도 경쟁하지 않는다. 무거운 blob CAS 재시도 루프를 타지 않는다.
- 집계 재계산 후 `mock:agg:<roundId>` 갱신

### 3.2 선생님 — `api/admin/[action].js`

| action | 메서드 | 권한 | 용도 |
|---|---|---|---|
| `mock-rounds` | GET | admin | 회차 목록 (`?grade=` 필터). 각 회차 제출률 포함 |
| `mock-round-save` | POST | **master** | 회차 개설·수정 |
| `mock-round-delete` | POST | **master** | 회차 삭제 (제출·집계 함께 삭제) |
| `mock-detail` | GET | admin | `?roundId=&schoolId=` 회차 상세. `schoolId` 주면 그 반만 |
| `mock-edit` | POST | admin | 점수 수정 / 집계 제외 |

- 개설·삭제는 `requireMasterSession`으로 마스터만. 조교는 조회만 한다.
- `mock-detail`의 미제출자 계산: `schoolId`가 있으면 그 반 blob 1개만 읽는다. 없으면(회차 관리 화면) 그 학년 반들의 blob을 읽는데, 이 화면에서만 일어난다.
- `mock-edit`은 `editedBy`에 관리자 actorId를 남기고 집계를 다시 계산한다.

### 3.3 학년 변경 — 기존 저장 경로 그대로

진급은 학생을 옮기는 게 아니라 **반의 `school.grade`를 바꾸는 것**이다(7장). 학교 설정의 기존 저장(PUT `/api/admin/school/[id]`)이 그대로 처리하므로 **새 action이 필요 없다.**

## 4. 등수·집계 규칙

- **표준 경쟁 등수**: 동점은 같은 등수, 다음은 건너뛴다 (88·88·85 → 1·1·3등). 기존 `totalRank`/`rankCounts` 규칙과 동일하게 맞춘다.
- `excluded: true`인 제출은 등수·평균·최고·분포에서 **완전히 빠진다**(분모에서도).
- **등급은 학생이 넣은 값만 쓴다.** 원점수→등급 자동 환산은 하지 않는다 — 회차마다 등급컷이 달라 틀린 등급을 성적표에 찍게 된다. 등급 미입력자는 `gradeDist`에서만 빠지고 원점수 등수에는 정상 포함된다.
- **응시자 5명 미만이면 학생 응답에서 `rank`/`tieCount`/`avg`/`max`를 `null`로 내린다.** 응시자가 소수일 때 평균과 내 점수로 남의 점수를 역산할 수 있다. 화면에는 "응시자가 적어 등수는 표시하지 않습니다"라고 쓴다. 선생님은 그대로 본다.
- **등수는 마감(`closeAt`) 후에만 학생에게 내려보낸다.** 마감 전에 보이면 늦게 내는 학생이 등수를 보고 점수를 맞춰 낼 수 있다. 마감 전에는 제출 현황(`84명 중 62명`)까지만 보여준다.

## 5. 학생 화면

### 5.1 로그인 직후 팝업

조건: 내 학년에 열린 회차가 있고 **내가 아직 미제출**일 때만, 세션당 1회.

```
📢 2026년 3월 학력평가 · 마감 4/2
   우리 학년 84명 중 62명 입력 완료

   영어 원점수  [  88  ] 점
   등급         [ 2등급 ▾ ]      (1~9등급 / 모름)

        [제출하기]   [나중에 할게요]
```

- 등급은 **드롭다운만**. 자유 입력이면 표기가 흔들려 나중에 필터링이 안 된다.
- `나중에 할게요`는 `sessionStorage`에 표시해 그 세션 동안만 숨긴다. 다음 로그인 때 다시 뜬다.
- 마감 24시간 이내면 마감일에 빨간 배지를 붙인다.

### 5.2 성적표 탭 상단 상시 카드

팝업을 닫은 학생도 언제든 들어오는 정식 입구다. 세 가지 상태를 가진다.

1. **미제출(마감 전)** — 팝업과 같은 입력 폼 + 제출 현황
2. **제출완료(마감 전)** — `88점 · 2등급 제출됨 · 마감 전까지 수정 가능 [수정]` + 제출 현황
3. **마감됨** — 결과 카드

### 5.3 결과 카드

```
2026년 3월 학력평가                          1학년
88점 · 2등급
학년 12등 / 84명  (동점 3명)
학년 평균 71.4점 · 최고 98점

[등급 분포 막대그래프 — 내 등급 막대만 강조색]
```

### 5.4 추이 그래프

기존 성적표의 RT/WT 추이 차트와 같은 Chart.js 스타일·색으로 맞춘다.

- 메인: 내 점수(실선) / 학년 평균(점선), x축은 회차(응시일 순)
- **학년이 바뀌는 지점에 세로 구분선과 `2학년 ▶` 라벨** — 1학년 3월부터 3학년 10월까지 한 그래프에 이어진다
- 보조: 등수 추이 (y축을 뒤집어 1등이 위로 오게)

## 6. 선생님 화면

### 6.1 회차 관리 (학원 전체 레벨)

학교 선택 화면(`renderSchoolGrid` 위)에 `📈 모의고사 회차 관리` 진입점을 둔다. 회차는 학년 단위라 특정 반 안에 있으면 어색하다.

- 회차 목록: 학년 필터, 응시일 내림차순, 각 행에 **제출률 `62/84 (74%)`**
- 회차 만들기: 학년(드롭다운) · 제목 · 응시일 · 입력 마감일 · 만점
- 행 클릭 → 학년 전체 상세: 반별 요약 표 · 미제출자 명단(반별) · 전체 순위표
- 개설·수정·삭제 버튼은 마스터에게만 보이고 서버에서도 마스터만 통과시킨다

### 6.2 반 사이드바 `📈 모의고사` 탭

`rAdmin()`의 메뉴 그룹 `업무`에, `성적 일괄 입력` 아래에 넣는다.

- 상단: 회차 선택 드롭다운(이 반 학년의 회차만)
- 요약 배너: `우리 반 18명 중 14명 입력 · 평균 76.2 (학년 71.4) · 최고 98 · 1등급 3명`
- 표: 이름 / 원점수 / 등급 / **학년 등수** / 제출시각 / `[수정]` `[제외]`
  - 미제출자는 회색 행 + `미제출` 배지
  - 미제출자를 체크해서 **기존 뿌리오 발송으로 독촉** (학생 관리의 일괄 발송 UI 재사용)
- 그래프 2개:
  1. 회차별 **우리 반 평균 vs 학년 평균** 라인
  2. 이번 회차 **반별 평균 비교** 막대 (우리 반 강조)
- 학생 이름 클릭 → **그 학생의 전 학년 모의고사 이력 모달** (성적 일괄입력의 학생 성적표 미리보기와 같은 패턴)

## 7. 진급 처리

**진급은 학생을 옮기지 않는다. 반 자체가 올라간다.**

한 반이 통째로 다음 학년이 되므로, 3월에 학교 설정에서 반의 `name`과 `grade`만 고치면 끝난다. 학생 목록도 ID도 그대로다.

```
고양국제고 1학년 A반  ──학교 설정에서 학년만 수정──▶  고양국제고 2학년 A반
(학생 18명, ID s401~s418 그대로 유지)
```

따라서 **모의고사 이력이 끊길 경로가 없다.** 반 이동 기능도, 학생 확인 창도, 이름·전화번호 매칭 안전망도 필요 없다.

이미 있는 기능(`rSchoolSettings`의 학년 입력칸)으로 처리되지만, 모의고사가 `grade`를 매칭 키로 쓰게 되면서 이 칸이 **조용한 실패 지점**이 된다. 두 가지를 보강한다.

### 7.1 학년 입력칸을 드롭다운으로

지금은 자유 텍스트라 `2학년`을 `2 학년`이나 `고2`로 치면, 그 반 학생 전원이 2학년 회차 대상에서 빠진다. 학생에게는 입력창이 아예 안 뜨고, 선생님은 "왜 아무도 안 냈지" 하게 된다. 에러도 나지 않아 알아채기 어렵다.

- 현존 학년 목록(`getSchoolSummaries()`의 `grade`를 정규화·중복제거)에서 고르는 드롭다운으로 바꾼다
- 새 학년이 필요한 경우를 위해 `+ 새 학년 입력` 항목을 둔다. 이때 입력값은 `normalizeGrade()`를 거치고, 비슷한 학년이 이미 있으면 그것을 쓸지 되묻는다
- 저장 시 서버도 `normalizeGrade()`를 적용한다 (클라이언트 검증만 믿지 않는다)

### 7.2 학년을 바꿀 때 확인창

```
이 반을 2학년으로 바꿉니다.
학생 18명이 앞으로 2학년 모의고사 대상이 됩니다.
지난 1학년 기록은 그대로 남습니다.
                            [취소]  [변경]
```

지난 기록이 남는다는 걸 명시하는 이유: 학년을 바꾸면 과거 성적이 날아갈까 봐 주저하게 되는데, 실제로는 제출이 회차에 붙어 있어 안전하다.

### 7.3 학년이 바뀐 뒤의 동작

| 대상 | 결과 |
|---|---|
| 과거 제출 | `mock:sub:<roundId>`에 그대로. 회차에 붙어 있어 반의 학년과 무관 |
| 과거 등수·평균 | 그 회차의 집계 그대로. 다시 계산되지 않음 |
| 학생 이력 화면 | 1학년·2학년 회차가 한 그래프에 이어짐 (3.1의 `history`는 학년으로 거르지 않는다) |
| 스냅샷 반 이름 | 제출 당시 이름(`고양국제고 1학년 A반`)이 그대로 남아 그때 소속을 보여줌 |
| 앞으로의 입력창 | 2학년 회차가 뜬다 |

**아직 마감되지 않은 1학년 회차가 있을 때 학년을 바꾸면** 그 회차에는 더 낼 수 없다(`mock-submit`이 학년 불일치로 403). 학년을 바꾸는 시점은 학년말·학년초라 실무상 겹치지 않지만, 7.2의 확인창에서 열려 있는 회차가 있으면 그 사실을 함께 알린다.

## 8. 엣지케이스

| 상황 | 처리 |
|---|---|
| 마감 후 학생이 제출 시도 | 403 `입력이 마감되었습니다`. 선생님은 언제든 수정 가능 |
| 마감 전 등수 요청 | 서버가 `rank`를 내려보내지 않음. 제출 현황만 노출 |
| 응시자 5명 미만 | 학생에게 `rank`/`tieCount`/`avg`/`max`를 `null`로. 선생님은 그대로 봄 |
| 회차 삭제 | 제출·집계도 함께 삭제. 확인창에 제출 건수를 명시 |
| 탈퇴 학생의 제출 | 등수·평균에 그대로 포함(응시는 했으므로). 미제출 독촉 명단에서만 제외 |
| 점수 범위 밖 / 등급 이상값 | 서버에서 400. 클라이언트 검증만 믿지 않음 |
| 집계 캐시 없음·손상 | 그 자리에서 재계산 후 저장 (self-healing) |
| 학년에 반이 하나뿐 | 그대로 노출하되 `응시자 N명`을 함께 적어 오해를 막음 |
| 회차 학년과 학생 학년 불일치 | 제출 403. 학년을 바꾼 직후 오래된 화면에서 낼 때 발생 가능 |
| 반의 학년을 바꿈 | 과거 제출·집계는 회차에 붙어 있어 그대로. 앞으로의 회차만 바뀜 (7장) |

## 9. 테스트

`tests/course.test.mjs` 패턴을 따라 `tests/mock.test.mjs`를 만든다.

- 등수 계산: 동점 처리(88·88·85 → 1·1·3), `excluded` 제외 시 분모 감소
- `normalizeGrade`: `고1`/`1학년`/` 1학년 `이 같은 키로 접힘
- 마감 판정: `openAt` 전 / 사이 / `closeAt` 후
- 응시자 5명 미만일 때 학생 응답에서 등수·평균이 `null`인지
- 집계 캐시가 없을 때 재계산되는지
- 학년이 바뀌어도 `history`에 과거 학년 회차가 남는지 (학년으로 거르지 않는지)

## 10. 구현 순서

1. `api/_lib/mock.js` — 데이터 접근·등수·집계·정규화 (+ 단위 테스트)
2. `api/admin/[action].js` — 회차 CRUD, 상세, 수정 (마스터 권한 포함)
3. `api/student/[action].js` — `mock` 조회, `mock-submit`
4. 학생 화면 — 성적표 상시 카드 → 결과 카드 → 추이 그래프 → 로그인 팝업
5. 선생님 화면 — 반 `모의고사` 탭 → 회차 관리 화면
6. 학교 설정의 학년 입력칸을 드롭다운으로 + 변경 확인창 (7장)
7. `index.html` 변경 내역(CHANGELOG) 갱신

4번까지 끝나면 학생 입력은 실제로 동작한다. 5·6번은 그 위에 얹는 구조라 중간에 멈춰도 데이터가 깨지지 않는다. 다만 **6번은 첫 진급(내년 3월) 전에는 반드시 끝나야 한다** — 그전까지는 자유 텍스트 학년 칸이 그대로라 오타 한 번에 반 하나가 통째로 회차에서 빠진다.

## 11. 의존 가정

- **학생 ID는 전역 유니크하다.** `next-student-id`가 전역 카운터로 채번하고 `findStudentByCredentials`의 로그인도 이 가정 위에 서 있다. 이 가정이 깨지면 모의고사 제출이 다른 학생 것을 덮어쓴다.
- **진급은 반 단위로 통째로 올라간다**(7장). 학생 일부만 다른 반으로 흩어지는 운영을 하게 되면 그 학생들의 ID를 유지할 방법이 없어, 그때 가서 반 이동 기능이 필요해진다.
- `school:summary` 해시에 `grade`가 들어 있어 학년 목록을 blob 없이 뽑을 수 있다.
- Chart.js 4.4.1이 이미 로드돼 있어 그래프에 새 의존성이 필요 없다.
