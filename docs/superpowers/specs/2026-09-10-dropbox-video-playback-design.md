# 드롭박스 보안 재생 + 시청 기간 설계

## 배경

`lecture.html`의 재생 화면(`playerScreen`)은 지금까지 "재생 준비 중" 안내만 있고 실제 재생이 없었다. 유료 판매 강의는 러넥스(DRM)를 계속 쓰기로 했지만, **학원 학생 전용 보충 영상**(숙제 해설 등)까지 러넥스에 올리기엔 용량·비용이 부담이라 이 영상들은 이미 계약된 드롭박스(유료 2TB 계정)에 두고 사이트 안에서 재생한다.

사용자 요구사항(확정):
- 대상: 학원 학생 전용 보충 영상. 무료 맛보기 영상은 없음.
- 재생: 로그인한 사람만. 학생은 재생 버튼만 누르면 바로 보여야 함 — 확인 절차는 전부 뒤에서 처리.
- 보안: 내려받기 어렵게. 방식은 "확인 후 임시 주소 발급" + 이름·아이디 워터마크(위치 이동) + 다운로드 억제 + 억제 안내 문구.
- 시청 기간: 선생님이 영상 등록 시 시작일·종료일 지정, 기간 밖이면 못 봄.
- "다 봤어요" 버튼: 이번엔 유지. 다음 단계에서 자동 시청기록이 들어가면 제거.

### 보안의 한계 (사용자에게 설명·합의 완료)

브라우저에서 재생되는 영상은 완벽히 막을 수 없다. 이 설계의 목표는 "쉽게는 못 가져가고, 가져가면 누군지 드러난다"이다.
- 재생 중에는 개발자도구로 4시간짜리 임시 주소를 볼 수 있다.
- 화면 녹화는 막을 수 없다 — 대신 워터마크가 찍힌다. 단 워터마크는 화면 위에 겹친 요소라, 개발자도구를 다룰 줄 아는 사람은 지우고 녹화할 수 있다.
- 드롭박스 임시 주소는 수명이 4시간 고정이라, 시청 기간 종료 직전에 재생을 시작한 학생은 최대 4시간 더 볼 수 있다.

진짜 차단(DRM)이 필요한 영상은 러넥스에 둔다.

## 전체 흐름

```
[선생님]  드롭박스 앱으로 Apps/<앱이름>/videos/ 에 영상 파일을 끌어다 놓음 (사이트 경유 없음)
    ↓
[관리자 영상 관리]  "드롭박스에서 고르기" → dropbox-list → 파일 선택 → 시청 기간 입력 → 저장
    ↓                                                 (video.dropboxPath / availableFrom / availableUntil)
[학생 인강 목록]  카드에 기간 표시 ("~9월 20일까지" / "9월 15일부터" / "시청 기간 종료")
    ↓   ※ 목록 응답에는 dropboxPath 절대 없음 — playable/availability만
[재생 화면 열림]  즉시 play-url 요청 (학생은 모름) → 서버: 로그인 → 이 사람 목록에 있는 영상인지
    ↓                → 파일 있는지 → 기간 안인지 → 드롭박스 임시 주소(4시간) 발급
[재생]  우리 재생기(자체 컨트롤) + 이름·아이디 워터마크(30초마다 이동) + 억제 안내 문구
```

영상 데이터는 드롭박스 → 학생에게 직접 전달되어 Vercel 전송량을 쓰지 않는다. 우리 서버가 중계하는 방식은 Vercel 무료 요금제 월 100GB를 영상 몇 편이면 넘기고, 보안 이득도 거의 없어 채택하지 않았다.

## 드롭박스 연결 설정 (사용자 작업)

아직 드롭박스 열쇠(`DROPBOX_APP_KEY`/`DROPBOX_APP_SECRET`/`DROPBOX_REFRESH_TOKEN`)가 Vercel에 없다. 후기 사진과 이 영상 재생이 같은 연결을 쓴다. 만들 때:
- 드롭박스 앱 종류는 **App folder(앱 전용 폴더)** — 사이트는 `Apps/<앱이름>/` 안만 볼 수 있고 나머지 파일엔 접근 불가. (전체 드롭박스 접근으로 만들면 안 됨)
- 앱 이름은 영문 권장(예: `oheng-media`) — 이 이름이 폴더 이름이 된다.
- 권한: `files.metadata.read`(목록), `files.content.read`(임시 주소), `files.content.write`(후기 사진 업로드), `sharing.write`(후기 사진 공유 링크).
- refresh token은 만료 없는 방식(offline)으로 발급.
- 앱 폴더 안에 `videos` 폴더 생성. 후기 사진은 같은 앱 폴더 안 `review-images/`에 쌓인다(기존 코드 경로 그대로).

값은 사용자가 Vercel 대시보드에 직접 넣는다. 세션에서 값을 요청하거나 보지 않는다.

## 데이터 모델 (video 레코드에 필드 추가)

```
video:{id} → {
  ...기존 필드 (title, month, week, mediaKey, note, allowSchoolIds, excludeStudentIds,
                includeStudentIds, downloadPolicy, createdAt, updatedAt),
  dropboxPath:    '' | '/videos/파일명.mp4'   // 앱 폴더 기준 경로
  availableFrom:  '' | 'YYYY-MM-DD'           // 한국 시간 그날 0시부터
  availableUntil: '' | 'YYYY-MM-DD'           // 한국 시간 그날 23:59:59.999까지
}
```

`normalizeVideo`(`api/_lib/video.js`)가 서버에서 검증한다:
- `dropboxPath`: `/videos/`로 시작(대소문자 무시), `..` 없음, 확장자 `.mp4 .m4v .mov .webm` 중 하나. 아니면 `''`로 저장.
- 날짜: `YYYY-MM-DD` 형식이 아니면 `''`.
- 두 날짜가 다 있는데 시작일 > 종료일이면 `api/videos/[action].js`의 `save` 액션이 400 `시작일이 종료일보다 늦습니다`로 거부.

기존 영상은 새 필드가 없으므로 `dropboxPath:''`(재생 불가, 기존 안내 유지), 기간 제한 없음 — 하위호환.

## 시청 기간 판정

`getAvailability(video, now = Date.now())` → `'open' | 'upcoming' | 'ended'` (`api/_lib/video.js`)
- 두 날짜 모두 비어있으면 `'open'`.
- 경계는 한국 시간 기준으로 명시 계산한다(Vercel 서버는 미국 리전·UTC로 돈다):
  `Date.parse(availableFrom + 'T00:00:00+09:00')`, `Date.parse(availableUntil + 'T23:59:59.999+09:00')`.
- `now < 시작` → `'upcoming'`, `now > 종료` → `'ended'`, 그 외 `'open'`.

화면 가리기와 별개로 **서버의 재생 주소 발급에서 반드시 막는다.**

## 목록 응답 (학생·회원 공통 규칙)

학생 목록 `listVideosForStudent`(`api/_lib/video.js`)와 회원 강좌 목록 `listVideosForEntitlements`(`api/_lib/course.js`) 둘 다:
- **`dropboxPath`를 절대 포함하지 않는다.** 특히 `listVideosForStudent`는 지금 관리자 전용 필드 몇 개만 빼고 나머지를 통째로 내려보내는 구조라, 새 필드를 명시적으로 빼지 않으면 그대로 샌다 — 제외 목록에 반드시 추가.
- 추가 필드: `playable`(드롭박스 파일이 지정됐는지), `availability`, `availableFrom`, `availableUntil`.

## 재생 주소 발급

새 파일 `api/_lib/playback.js`:
- `listVisibleVideosForOwner(owner)` — "이 사람 목록에 보이는 영상"을 계산하는 단일 기준.
  - 학생: `listVideosForStudent(schoolId, studentId)` ∪ 학생 수강권의 `listVideosForEntitlements`
  - 회원: 회원 수강권의 `listVideosForEntitlements`
  - `api/videos/[action].js`의 기존 `mine` 액션도 이 함수를 쓰도록 바꿔서, "목록에 보이는 것"과 "재생 가능한 것"이 한 곳에서 정해지게 한다(동작은 그대로).
- `resolvePlayUrl(owner, videoId, now)`:
  1. `videoId`가 보이는 영상 목록에 없음 → 404 `볼 수 없는 영상입니다` (존재 여부를 드러내지 않도록 403 대신 404)
  2. 원본 레코드(`getVideo`)에 `dropboxPath` 없음 → 404 `아직 영상이 준비되지 않았습니다`
  3. 기간 `upcoming` → 403 `M월 D일부터 볼 수 있어요`, `ended` → 403 `시청 기간이 끝났어요`
  4. 드롭박스 임시 주소 발급 → 200 `{ url }`. 드롭박스 오류(연결 전 포함) → 502 `영상을 불러오지 못했습니다`

원칙: **목록에 보이는 영상이면 재생된다.** 회원이 산 강좌에 드롭박스 영상이 들어있으면 그 회원도 재생된다 — 유료 강좌엔 드롭박스 영상을 넣지 않는 운영으로 대응(사용자 합의).

## 드롭박스 모듈 추가 (`api/_lib/dropbox.js`)

- `listVideoFiles()` → `{ files: [{ path, name, size }], folderMissing }`
  - `files/list_folder`로 `/videos` 조회(하위 폴더 제외), `has_more`면 `files/list_folder/continue`로 끝까지.
  - 파일만, 허용 확장자만 남김. 이름순 정렬.
  - 폴더가 없으면(`path/not_found`) `{ files: [], folderMissing: true }`.
- `getTemporaryLink(path)` → 문자열 주소. `files/get_temporary_link` 사용(수명 4시간, 구간 요청 지원 → 건너뛰기 재생 가능).
- 접근 토큰 캐시: 지금은 호출마다 새 토큰을 받는데, "누르면 바로 재생"을 위해 모듈 수준에서 만료 1분 전까지 재사용한다(`expires_in` 기준). 후기 사진 업로드도 같은 캐시를 쓰게 된다.

## API (`api/videos/[action].js`에 액션 2개 추가 — 새 파일 없음, 함수 12개 유지)

- `play-url` (GET `?videoId=`, 학생/회원 세션 — `requireOwnerSession`) — 관리자 게이트보다 위.
  - `checkRateLimit('play-url', ownerType:ownerId, 30, 60)` 초과 시 429.
  - 응답 헤더 `Cache-Control: no-store`.
- `dropbox-list` (GET, 관리자) — 관리자 게이트 아래. `listVideoFiles()` 결과 그대로. 드롭박스 미연결이면 503 `드롭박스가 아직 연결되지 않았습니다`.
- `save`에 시작일 > 종료일 검증 추가.

## 학생 화면 (`lecture.html`)

### 목록 카드
- `open` + 종료일 있음: `~9월 20일까지` 작은 표시
- `upcoming`: `9월 15일부터` 표시
- `ended`: `시청 기간 종료` 표시 + 흐리게
- 카드 클릭은 그대로 재생 화면으로 이동(재생 화면에서 상태 안내).

### 재생 화면
- `playable && availability==='open'`이면 재생기, 아니면 상태별 안내 상자:
  - 파일 없음: `아직 영상이 준비되지 않았어요` (기존 "콜러스 연동 후" 문구는 더 이상 사실이 아니므로 교체)
  - 기간 전/후: 서버 메시지와 같은 문구
- **화면이 열리는 순간 `play-url`을 미리 요청**해 주소를 받아둔다 → 재생 버튼을 누르면 기다림 없이 시작. 받는 동안 `영상 불러오는 중...`.
- **자체 컨트롤 재생기.** 기본 `controls`를 쓰지 않는다. 이유: 다운로드·전체화면 버튼을 끄는 `controlsList`는 크롬 전용이라 사파리·아이폰에선 무시되고, 아이폰 기본 전체화면은 영상만 키워 워터마크가 사라진다. 자체 컨트롤: 재생/일시정지, 진행 막대(건너뛰기), 현재/전체 시간, 음소거, 속도(1·1.25·1.5·2배), 전체화면.
- `<video>` 속성: `playsinline disablePictureInPicture preload="metadata"`. 재생기 영역 우클릭 막음.
- **워터마크:** 학생은 `이름 · 아이디`(`student.id`가 로그인 아이디), 회원은 `이름 · 전화번호 뒤 4자리`(전화 없으면 이메일 앞 2자 + `***` + 도메인). 전화번호 전체를 찍으면 영상이 유출될 때 학생 번호가 퍼지므로 가린다. 불투명도 약 35%, 클릭 통과, 30초마다 재생기 안 임의 위치로 이동.
- **전체화면:** 영상이 아니라 재생기 영역(영상+워터마크)을 키운다. `requestFullscreen`이 있으면 그걸로, 없으면(아이폰 사파리) 화면을 꽉 채우는 CSS 모드로 대체 — 어느 쪽이든 워터마크가 같이 따라간다.
- **억제 안내 문구**(재생기 바로 아래, 항상 표시): `🔒 {이름}님 전용 영상입니다. 녹화하거나 공유하면 화면에 표시된 이름으로 누구인지 확인됩니다.`
- 재생 중 주소가 만료돼 오류가 나면(화면을 4시간 넘게 열어둔 경우) `play-url`을 한 번 다시 받아 이어서 재생, 그래도 실패하면 `영상을 불러오지 못했습니다. 잠시 후 다시 시도해주세요.`
- 워터마크 이동 타이머는 다른 화면으로 넘어갈 때 반드시 정리한다(`render()`가 화면을 통째로 갈아끼우므로 안 치우면 계속 쌓임).
- "다 봤어요" 버튼은 그대로 유지.

## 관리자 화면 (`index.html` 영상 관리)

### 영상 추가/수정 폼
- **드롭박스 영상 파일** 칸: 현재 선택된 파일 이름(없으면 `선택 안 됨`) + `드롭박스에서 고르기` 버튼 + `선택 해제`.
  - 누르면 `dropbox-list` → 파일 이름·용량(MB) 목록, 하나 클릭하면 선택.
  - `folderMissing`: `드롭박스 앱 폴더 안에 videos 폴더를 만들고 영상을 넣어주세요`
  - 미연결(503): `드롭박스가 아직 연결되지 않았습니다`
  - `.mp4/.m4v`가 아니면 경고: `mp4가 아니면 일부 기기에서 재생되지 않을 수 있어요`
- **시청 시작일 / 시청 종료일**(날짜 입력, 선택) + 안내: `비워두면 제한 없이 볼 수 있어요. 한국 시간 기준, 종료일 밤 11시 59분까지.`
- 저장 요청에 `dropboxPath`, `availableFrom`, `availableUntil` 추가. 400(시작일>종료일)이면 폼 메시지로 표시.

### 영상 목록 표
- "콜러스 키" 칸을 **영상 파일** 칸으로: `드롭박스` / (기존 mediaKey만 있으면) `키 있음` / `미등록`.
- 제목 아래 작은 글씨로 기간: `9/15 ~ 9/20`, `~ 9/20`, `9/15 ~`, 종료된 건 `기간 종료`(빨강).
