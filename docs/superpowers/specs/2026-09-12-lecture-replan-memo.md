# 인강(oheng.co.kr) 기획 재점검 메모 — Codex 검토용 (2026-09-12)

## 이 문서의 목적

드롭박스 보안 재생이 실제로 동작하는 것을 사용자가 확인한 직후, 후속 요청이 한꺼번에 나왔다.
개별 수정으로 대응하기 전에 인강 서비스 전체 기획을 다시 점검한다. 이 문서는 (1) 현재 상태,
(2) 사용자 요청 8건, (3) 초안 설계·우선순위를 담고, Codex의 비판적 검토를 받기 위한 것이다.

## 서비스 구조 (현재)

- 한 Vercel 프로젝트, 두 화면 파일:
  - `index.html` (oheng.vercel.app): 학원 성적관리. 관리자(선생님) 화면 + 학생 성적표 화면(탭: 성적표·모의고사·제안하기·문의하기·설정).
  - `lecture.html` (oheng.co.kr): 인강 사이트. 비로그인 랜딩(강좌·선생님 소개·커리큘럼·후기) + 학생 로그인 후 영상 목록/재생 + 후기 게시판.
- 계정: 학생(학원 발급 ID/PW, 두 사이트 공통 세션 쿠키), 회원(휴대폰/구글, 유료 강좌 구매용), 관리자.
- 영상: `video` 레코드(제목·월/주차·허용 학교·학생 예외·`dropboxPath`·시청 시작/종료일). 드롭박스 앱 폴더 `/videos`의 파일을 관리자가 골라 연결. 재생은 `play-url`이 로그인→목록 가시성→기간 확인 후 4시간 임시 주소 발급. 자체 컨트롤 재생기 + 이름·아이디 워터마크(30초마다 이동) + 억제 안내.
- 시청 기록: `watch:{ownerType}:{ownerId}:{videoId}` — 지금은 학생 "다 봤어요"(self_confirmed)와 교사 정정(teacher_confirmed/exempt)만. 관리자 화면에서 볼 수 있는 UI는 없음(API만 있음).
- 출석: 별도로 `attendType`(주차별, 교사가 손으로 현강/인강/결석 입력)이 성적 레코드에 있음. 시청 기록과 연결 안 됨.
- 후기: `review:{id}` + 댓글. 학생/선생님 작성, 즉시 공개, 관리자 삭제. 화면은 카드 나열 + 상단 작성 폼.
- 제약: Vercel Hobby 서버리스 함수 12개(꽉 참 — 새 API는 기존 `[action].js`에 액션 추가), 요청 본문 4.5MB, 드롭박스 원본 그대로 재생(서버 영상 가공 불가), 관리자 화면은 다크모드에서 글자색 지정 안 된 곳이 흐리게 보임.

## 사용자 요청 (오늘, 우선순위 미정)

1. **워터마크가 거슬림** → 결정: 모서리에만 작게(중앙 점프 없음).
2. **"다 봤어요" 대신 자동 시청 기록** → 결정: 실제 재생한 구간이 90% 이상이면 완료(건너뛴 구간 제외, 2배속 허용). 선생님 확인 위치: **둘 다** — 영상 관리에서 영상별 학생 시청 현황 + 인강/현강 체크에 자동 반영. 자동 기록이 들어가면 "다 봤어요" 버튼 제거(이전 결정).
3. **성적표(index.html)에서 인강 진입** → 결정: 학생 탭에 '인강' 추가.
4. **강좌(영상) 목록 페이지가 너무 휑함** — 로그인 후 화면이 "1월 1주 · 1개 / Test / ~9월 19일까지" 카드 하나뿐.
5. **되돌아오는 경로 없음** — 영상 목록에서 "강좌 더보기"로 랜딩에 나가면 영상 목록으로 다시 들어올 버튼이 없음(새로고침해야 함). 후기 화면에서도 마찬가지.
6. **후기 작성이 실제 게시판처럼** — 지금은 카드 나열. "게시판 형태"의 구체 의미는 미확인(제목 목록+상세 페이지? 페이지 나누기? 분류? 조회수?).
7. **성적표에 인강 봤는지 표시** — 학생 성적표 화면에 그 주차 영상 시청 여부/비율.
8. **전체 기획 재점검** — 인강을 다시 엮는 김에.

## 초안 설계 (Codex가 뜯어볼 대상)

### A. 시청 기록 자동화 (요청 2, 7, 3의 데이터 기반)

- 클라이언트: 재생기가 `timeupdate`로 실제 재생한 구간을 초 단위 비트맵/구간 목록으로 모으고, 15초마다 + 일시정지/이탈 시 `watch-progress` POST `{videoId, watchedSeconds, duration, segments}`. 건너뛰기는 구간이 안 채워지므로 자동 제외. 배속은 실제 재생 위치 기준이라 자동 허용.
- 서버(`watch.js`): 레코드에 `progress: {watchedSeconds, duration, ratio, segments(압축), lastPositionSec, updatedAt}` 추가. `ratio >= 0.9`면 `status:'auto_completed', source:'player'`. 교사 정정은 그대로 우선. `self_confirmed`는 더 이상 생성하지 않음(기존 값은 유지·표시).
- 이어보기: `lastPositionSec`로 재생 화면 열 때 이어서.
- 관리자: 영상 관리 목록의 영상별 "시청 현황" → 허용 학교 학생별 % / 완료 / 마지막 시청일 (watch-admin-list 확장).
- 인강/현강 체크 자동 반영: 영상의 월·주차와 학생의 `auto_completed`가 맞으면 그 칸을 '인강'으로 **제안**(자동 확정 vs 제안만 — 결정 필요). 손으로 입력한 값은 덮어쓰지 않음.
- 성적표: 그 주차 영상 목록과 시청 % 표시(요청 7). 데이터는 `watch-mine` 확장.
- 우려: 구간 저장 용량(1시간 영상=3600초 → 비트 문자열이면 450바이트, 문제 없음), 15초 주기 쓰기 부하(학생 30명 × 동시 → Upstash 분당 120건, 괜찮음), 재생 화면 이탈 시 `sendBeacon` 필요.

### B. 학생 인강 화면 재구성 (요청 4, 5, 3)

- `lecture.html` 로그인 후 화면을 "내 강의실"로: 상단에 이번 주 영상 + 시청률 요약, 아래 주차별 목록(시청 % 뱃지·완료 표시·기간). 영상이 0개면 "이번 주 영상이 아직 없어요" 안내.
- 네비: 로그인 상태에서 항상 "내 강의실 / 강좌 더보기 / 후기" 링크 노출(현재는 browse 화면에서만 링크가 뜨고, 로그인 상태에선 "강좌 더보기"만). 이게 요청 5의 원인.
- `index.html` 학생 탭에 '인강' 추가 → **같은 주소 안의 `/lecture.html`로 이동**(사용자 결정 2026-09-12). 이유: 세션 쿠키는 도메인별(host-only)이라 oheng.vercel.app → oheng.co.kr 로 넘어가면 재로그인이 필요하지만, 두 파일이 같은 배포에 있으므로 상대 경로로 가면 로그인이 유지됨. 반대 방향(인강 → 성적표)도 `/index.html`로 같은 원리(루트 `/`만 리다이렉트되므로 `/index.html`은 성적 앱이 그대로 뜸).
- 사용자 결정(2026-09-12): 워터마크는 모서리에만 작게; 자동 시청 완료 기준 90%; 선생님 확인은 영상별 현황 + 인강/현강 체크 반영 둘 다; 후기 게시판은 제목 목록 + 클릭 시 글 열림(페이지 나누기, 작성 시 제목 칸).

### C. 후기 게시판 형태 (요청 6)

- 후보: (a) 제목 목록 + 클릭 시 상세(댓글은 상세에서) + 페이지 나누기, (b) 지금 카드형 유지 + 분류/정렬/페이지만 추가. 사용자 의도 확인 필요.
- 데이터는 `review:index` 배열이라 페이지 나누기는 서버에서 slice로 충분.

### D. 워터마크 (요청 1)

- 모서리 4곳 중 하나에 작게(글자 11px, 투명도 30%), 30초마다 모서리 이동. 중앙 점프 없음. 전체화면 유지.

### 우선순위 초안

1. D(작음, 즉시) → 2. A 서버+재생기(핵심 가치: "실제로 들었는지 확인") → 3. B(내 강의실 + 네비 + 성적표 인강 탭) → 4. A 관리자 화면 + 성적표 표시 → 5. C 게시판.

1. 이 분해와 순서가 맞는가? 하나로 묶어야 하거나 더 잘게 쪼개야 할 것은?

5. 12개 함수 한도 안에서 새 액션 배치(`api/videos/[action].js`가 커지는 문제).
6. 놓친 위험.
